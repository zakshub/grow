# MVP Build Plan

## Objective

Build the smallest version of Grow that can test whether structured career discovery creates useful direction for real participants.

The MVP should validate guidance quality before national scale, advanced automation, or a large technical stack.

## MVP success question

Can Grow take a participant who is genuinely unsure about career direction and produce a recommendation that the participant understands, considers relevant, and can test through a practical next step.

## MVP participant scope

Primary pilot participants:

1. Grade 8 through graduation
2. Karachi first
3. Urdu first
4. Smartphone access assumed
5. Voice input supported where practical

A small number of career reset adults may be accepted to test the secondary track, but they should not distort the first student focused pilot.

## MVP features

### Participant intake

1. WhatsApp entry
2. Consent
3. Age
4. Education level
5. City and area
6. Current status
7. Referral source
8. Minor detection

### Discovery

1. Open ended career confusion question
2. Interest discovery
3. Strength stories
4. Work preference questions
5. Constraint questions

### Assessment

Initial dimensions should be limited to a useful core rather than every possible trait.

Recommended first set:

1. Logical reasoning
2. Verbal expression
3. Creativity
4. Social orientation
5. Persuasion
6. Detail orientation
7. Organisation
8. Curiosity and research
9. Practical orientation
10. Independence and collaboration preference
11. Persistence
12. Risk and ambiguity preference

### Interest clusters

Use the six broad vocational interest families as a starting structure.

1. Practical
2. Investigative
3. Creative
4. Social
5. Enterprising
6. Organised

### Work values

Capture at least:

1. Income
2. Stability
3. Independence
4. Social impact
5. Creativity
6. Fast entry into earning
7. Remote work preference
8. Continued education willingness

### Practical experiments

Create an initial library for at least six broad career families.

Each experiment should take approximately 15 to 45 minutes.

### Recommendation

Return three to five ranked career directions.

Each should include:

1. Fit explanation
2. Supporting evidence
3. Main tradeoff
4. Required learning route
5. Practical next step
6. Confidence

### Human review

During MVP, all final recommendations should be reviewed by a human before delivery.

This gives Grow correction data before trusting automation.

### Fee flow

Support:

1. PKR 500 standard
2. PKR 200 reduced
3. Free after human approval

### Follow up

At minimum:

1. Seven day follow up
2. Thirty day follow up

## MVP operator tools

A full dashboard is not required on day one.

The first operator view must still show:

1. Participant
2. Stage
3. Assessment summary
4. Missing evidence
5. Proposed recommendation
6. Human review status
7. Fee status
8. Follow up status

This can begin as a simple internal interface and later become a full dashboard.

## MVP data requirements

Store structured records for:

1. Participant profile
2. Consent
3. Referral source
4. Assessment evidence
5. Assessment scores
6. Confidence
7. Practical experiment
8. Recommendation
9. Human correction
10. Fee status
11. Follow up outcome

## MVP not included

Do not delay the MVP for:

1. Full national career database
2. Every regional language
3. Advanced parent portal
4. Large school administration system
5. Complex gamification
6. Native mobile application
7. Automatic national salary prediction
8. Advanced machine learning trained on Grow data
9. Full alumni network
10. White label institutional product

## Pilot process

### Step 1

Recruit an initial warm network cohort.

### Step 2

Run the discovery process with close operator observation.

### Step 3

Record every point where participants become confused, bored, defensive, or disengaged.

### Step 4

Compare automated interpretation with human interpretation.

### Step 5

Run practical experiments.

### Step 6

Deliver recommendations.

### Step 7

Interview participants about whether the recommendation feels accurate and useful.

### Step 8

Follow up on actual action.

### Step 9

Promote only repeated learning into the brain.

## MVP quality gates

Do not progress to larger scale until:

1. Most participants understand the purpose
2. Assessment completion is acceptable
3. Recommendations show meaningful differentiation
4. Human reviewers do not repeatedly overturn the same logic
5. Practical experiments add useful evidence
6. Participants can explain why their recommended paths fit
7. Privacy and minor flows are operational
8. Opt out works correctly

## First technical build order

1. Repository foundation and schemas
2. Participant and consent model
3. WhatsApp webhook
4. Conversation state machine
5. Structured evidence model
6. Assessment question engine
7. Operator review view
8. Career profile model
9. Recommendation logic
10. Practical experiment workflow
11. Reporting
12. Follow up automation

## MVP principle

Do not automate away the learning phase.

The first purpose of the MVP is to discover how the service should work, not to prove that every human step can already be removed.
